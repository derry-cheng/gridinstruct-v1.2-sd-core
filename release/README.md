# GridInstruct v1.2-sd-core remediation candidate

This directory contains a compact, hash-bound local submission candidate. The canonical 95,479-record JSONL table is referenced once under `data/`; the near-neighbor-free partitions are stored as ID-only manifests so that the project does not contain a second copy of the 510 MB table. Full split materialization is a temporary benchmark step under `/tmp` and must not be included in an archive. The current reviewer-access map is `reviewer_access_manifest_2026-08-13.json` and records hashes for the current inspectable artifacts without copying the dataset.

`sd_remediation_manifest_2026-08-12.json` records the exact local artifacts, completed gates, and external gates that remain open. The current closeout is summarized in `../reports/sd_closeout_status_2026-08-13.json`; it also binds the 2026-08-12 CPU target-hidden replay, the exact-surface stress baseline, and their figures. The candidate is not a public accession: raw scenario and candidate ledgers, completed double reviews, public repository/DOI, and real author, CRediT, and funding metadata still require release-owner action.

The replay boundary is deliberately split. Row-level audits and TF--IDF baselines are locally reproducible from the canonical table and ID manifests. The exact character-surface stress split is recorded in `reports/exact_surface_component_split_v1.2_sd_core.json`, with its target-hidden nine-row diagnostic in the adjacent report; both remain lexical diagnostics. The 160 fixed-control AC replays are evidence for the registered case set only; they do not stand in for the missing full-population scenario ledger. `reports/evidence_reconciliation_v1.2_sd_core.md` explains why the legacy construction receipt and current row-integrity receipt are retained separately.
