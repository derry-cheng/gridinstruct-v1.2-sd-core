# 国际规章数据重构与验证计划

**问题**：新增的 NERC 与欧盟运行规章已经形成独立国际规则探针，但当前正文存在标准来源归属错误，512 条探针中有 256 条回答包含语义空转句，需要在不扰动 95,479 条核心数据和物理实验的前提下完成一次受控重构。

**方法主张**：通过“正式来源条款—类型化规则卡—直接英文生成—管辖区隔离划分—结构化与词汇诊断—双人复核”的闭环，形成可追溯、可复现且边界清楚的国际规则扩展。

**日期**：2026-08-20

## 一、范围冻结

本轮必须重构的对象只有 8 张国际规则卡、512 条国际规则问答记录、4 个国际探针划分、国际检索基线、128 条双人复核任务及其论文和归档证据。核心 95,479 条英文记录、核心 17 张中国来源规则卡、核心数据划分、AC 潮流、AC-OPF、N−1、安全包络、核心分类和生成基线均保持冻结。当前核心表共有 386,484 个规则链接，其中 `INTL_` 链接为 0，因而国际探针修改不会改变核心任务标签或物理真值。

如果后续决定把国际规则加入核心合规检查、规则问答或调度动作任务，应另立一次核心数据版本升级；届时必须重新生成受影响任务、重新划分、重跑核心基线和全部主张审计。本计划不包含这条扩展路线。

## 三、论文实验叙事

正文只保留国际扩展的数据构成、来源边界、四类划分和一组紧凑诊断结果。主要论证是“新增规则已形成独立、可追溯的数据域，并可用于管辖区条件化评估”。人工复核协议和逐卡结果可放在补充材料。国际探针不进入核心 95,479 条数据的主结果表，也不与 AC-OPF 或 N−1 物理验证合并解释。

本轮明确不增加大模型训练、Transformer 微调、额外网络系统或更多国家规章。现有 512 条数据足以暴露来源迁移问题，先修复数据语义质量和证据闭环。

## 四、实验与验证模块

### B1：正式来源与规则卡合同审计

**验证主张**：8 张规则卡真实对应 4 项 NERC 标准和欧盟 2017/1485 的 4 个条款。

**执行内容**：逐卡检查标准编号、标题、条款定位、正式来源 URL、访问日期、规则摘要、适用主体、证据字段和阈值来源。NERC 四张卡应分别对应 TOP-001-6、TOP-002-5、FAC-011-4、VAR-001-5；欧盟四张卡对应 Article 18、25、33、72。删除任何从中国数据策略移植到国际卡的数值阈值。论文正文和参考文献同步列明四项 NERC 标准，不能继续把四张卡统称为 TOP-001-6。

**输入**：`rules/international_rule_profiles.json`、`metadata/international_rule_profile_matrix.csv`、正式标准页面或 PDF。

**产物**：更新后的规则卡与矩阵；一份逐卡来源审计报告；正文来源段落修正。

**验收门槛**：规则卡数为 8；标准编号集合精确等于预注册集合；每卡只有一个明确管辖区和至少一个条款定位；正式来源可访问；所有规则摘要能由对应条款直接支持；国际卡不声明无来源的通用数值阈值。

**停止条件**：任一标准文本、版本或条款无法从正式来源核实，则停止生成该卡的数据，先修正来源合同。

**论文位置**：Methods 的输入与来源、规则卡构造；Data Records 的国际扩展说明。

**优先级**：MUST-RUN。

### B2：直接英文生成器修复与 512 条数据重构

**验证主张**：国际探针由类型化规则合同直接生成英文，回答内容自然、具体且保留来源边界。

**执行内容**：修复 `generate_international_rule_probe.py` 中 `focus_clauses + focus` 的机械拼接，为四种关注点分别编写有信息量的句子模板。增加生成测试，禁止 `X is X`、重复关注点、空泛占位词和未在规则合同中出现的义务。先在临时目录生成候选表，通过比较后再替换正式文件。

**数据规模**：8 张卡 × 4 类受众 × 4 类交付形式 × 4 类关注点 = 512 条，每卡 64 条。

**自动指标**：记录数、每卡记录数、唯一标识、规则链接、直接英文生成标志、来源字段完整率、唯一 instruction/output 数量、禁用模板命中数、JSONL 解析错误数。

**人工抽查**：每卡至少 8 条，覆盖四类交付形式与四类关注点；检查问题与回答匹配、条款忠实性、语言自然度和证据字段合理性。该 64 条快速抽查只用于生成门禁，不能代替后续双人复核。

**验收门槛**：512/512 可解析；每卡 64 条；重复或缺失 ID 为 0；每条恰好一个有效 `INTL_` 规则链接；生成模式全部为 `direct_english_from_typed_rule_contract`；语义空转模板命中数为 0；人工快速抽查严重错误为 0。

**停止条件**：任一卡出现来源不一致，或自动禁用模板命中数大于 0，不得进入划分和实验阶段。

**论文位置**：Methods 的规则卡构造；Data Records 的国际探针构成。

**优先级**：MUST-RUN。

### B3：划分重建与泄漏审计

**验证主张**：跨管辖区划分和同管辖区变体留出回答不同的迁移问题。

**执行内容**：使用修复后的 512 条数据重建四个折：欧盟训练/NERC 测试、NERC 训练/欧盟测试、欧盟内部变体留出、NERC 内部变体留出。即使 ID 保持稳定，也必须重新生成划分报告和文件哈希，避免旧内容与新数据绑定。

**验收门槛**：总记录数为 512；跨管辖区折的训练和测试管辖区完全分离；同管辖区折的 `answer_variant` 训练与测试集合无交叉；每折训练/测试 ID 无交集；所有 ID 均存在于新数据；四折分母与预注册设计一致。

**停止条件**：出现一条 ID 重叠、管辖区混入或变体泄漏即停止，先修复划分逻辑。

**论文位置**：Methods 的数据划分；Technical Validation 的隔离审计。

**优先级**：MUST-RUN。

### B4：国际探针基线与捷径诊断

**验证主张**：重构后的国际探针能够暴露跨管辖区迁移与同域表面变体迁移的差异。

**对照系统**：当前字符 TF–IDF 最近邻基线；目标复制下界；移除 `rule_id` 与 `standard_id` 的输入诊断。最近邻方法是确定性的，无需多随机种子。若新增随机模型，再使用 3 个种子并报告均值与标准差。

**主要指标**：规则卡 ID 准确率、标准 ID 准确率、管辖区准确率、条款精确匹配、证据字段 F1。次要指标为回答 exact match、token-F1 和平均最近邻相似度。所有指标必须附测试分母。

**验收门槛**：四折全部完成；预测条数等于各折测试分母；指标可由保存的预测逐条重算；移除显式标识后的诊断仍能运行；论文只解释划分难度和词汇迁移。无需追求旧分数不变，数据修复引起的合理变化应如实更新。

**停止条件**：若任一指标无法从预测文件重算，或无标识输入仍泄露目标字段，则不更新论文结果，先修复实验输入。

**表图目标**：正文现有国际探针表格的一行；如篇幅允许，在补充材料放四折结构化指标矩阵。无需新增正文表格。

**优先级**：MUST-RUN；无标识输入诊断属于 MUST-RUN，因为它直接回应捷径质疑。

### B5：双人复核、论文同步与发布冻结

**验证主张**：国际规则数据经过独立来源与语言复核，论文、数据和公开归档引用同一版本。

**执行内容**：从新数据按每卡 16 条重新抽取 128 条样本，生成每条两份互盲任务，共 256 个 reviewer assignments。复核维度为来源支持、条款匹配、管辖区正确性、英文自然度、证据字段充分性和是否含未授权阈值。两位复核者独立完成后计算逐项一致率、Cohen's kappa 或适合类别结构的一致性统计，并对分歧仲裁。随后更新正文中的 NERC 标准描述、512 条数据质量和基线数字，重建 LaTeX、证据绑定清单和公开归档。

**验收门槛**：128 条样本全部获得两份独立结果；缺失评价为 0；全部分歧完成仲裁；严重来源错误为 0；论文数字与新报告逐项一致；LaTeX 无硬错误、未定义引用和 overfull box；公开包匿名下载与本地归档哈希一致。

**停止条件**：人审未完成时，论文只能写“复核任务已准备”，不得写成人工验证通过。正式数据 DOI 未获得时，Data Availability 保留真实公开审阅地址并将 DOI 标为待外部完成。

**论文位置**：Technical Validation 的人工复核；Data Availability；参考文献。

**优先级**：自动重建、论文同步和归档为 MUST-RUN；独立人审属于投稿前外部门禁。

## 六、建议命令顺序

以下命令均在项目根目录运行，仅使用本地 CPU/MPS。正式执行时先将生成结果写入临时路径，全部门禁通过后再提升为当前文件。

```bash
python3 scripts/generate_international_rule_probe.py \
  --rules rules/international_rule_profiles.json \
  --matrix /tmp/international_rule_profile_matrix.csv \
  --data /tmp/international_rule_probe.jsonl \
  --report-json /tmp/international_rule_probe.json \
  --report-md /tmp/international_rule_probe.md

python3 scripts/create_international_rule_probe_splits.py \
  --input /tmp/international_rule_probe.jsonl \
  --manifest /tmp/international_rule_probe_splits.json \
  --report /tmp/international_rule_probe_splits_report.json

  --data /tmp/international_rule_probe.jsonl \
  --splits /tmp/international_rule_probe_splits.json \
  --output-prefix /tmp/international_rule_probe_baseline

python3 scripts/create_international_rule_review_assignments.py \
  --data /tmp/international_rule_probe.jsonl \

  --seed 20260820 \
  --output-prefix /tmp/international_rule_review_assignments
```

## 七、计算与人力预算

本计划 GPU 时数为 0。512 条数据生成、四折划分和字符 TF–IDF 最近邻基线均可在本地 CPU 完成，自动计算总耗时预计低于 1 小时。正式来源逐卡核验预计 2–4 小时。128 条样本的双人独立复核共有 256 份任务，按每份 1.5–2.5 分钟估计，总计约 6–10 人时，仲裁时间另计。最大瓶颈是独立人审和正式数据 DOI，计算资源不是瓶颈。

## 八、风险与处理

来源合同风险：NERC 四项标准在正文和参考文献中被错误合并。处理方式是先冻结标准编号与正式来源，再生成数据。

模板质量风险：唯一输出数量为 512 仍可能包含语义空转。处理方式是增加禁用模式、语义内容断言和逐卡人工抽查，不能继续只用唯一性作为质量门槛。

捷径风险：输入中直接出现标准名和规则标识，结构化准确率可能只反映复制。处理方式是保留原始基线，同时增加移除显式标识的诊断，正文只报告数据集可学习性和迁移边界。

版本漂移风险：数据、划分、基线、论文和公开包可能指向不同哈希。处理方式是按数据→划分→预测→论文→归档的顺序单向冻结，最后一次性重建证据绑定。

范围膨胀风险：国际规章改动被误扩展到 95,479 条核心数据和物理实验。处理方式是检查核心表 `INTL_` 链接必须继续为 0；若该值变化，停止本计划并另立核心版本升级方案。
